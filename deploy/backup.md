# النسخ الاحتياطي واسترجاع Rawmat

تتضمن القاعدة بيانات الحسابات والتكاليف والمستلمين. اجعل ملفات النسخ مقروءة للمسؤول فقط، واحفظ نسخة مشفّرة خارج الخادم. خزّن مفتاح فك التشفير في مكان مستقل عن خادم التطبيق.

## النسخ أثناء التشغيل

نفّذ من جذر نسخة المشروع على خادم Linux باستخدام ملفات البيئة نفسها التي تستخدمها لتشغيله.

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml exec -T app \
  /nodejs/bin/node apps/server/dist/cli/database-backup.js create
```

تقرأ الأداة SQLite عبر واجهة النسخ الاحتياطي، وتتحقق من سلامة النسخة وعلاقاتها قبل نشرها في `/data/backups`. يطبع الأمر مسار الملف ويحتفظ بآخر 14 نسخة أنشأتها الأداة على وحدة البيانات. استخدم هذا الأمر قبل ترقية التطبيق، وخصّص مساحة كافية للنسخ وللملف الجاري إنشاؤه.

## الجدولة الليلية والنسخة المشفّرة

ثبّت `age` و`rclone` على الخادم واضبط وجهة النسخ في حساب التشغيل. ضع مفاتيح `age` العامة للمستلمين في `/etc/rawmat/backup-recipients.txt`. احفظ السكربت التالي في مجلد خاص خارج نسخة Git واضبط مساراته ووجهته. يستخدم النسخة المحلية ويُرسل ملفًا مشفّرًا إلى الوجهة. اضبط مدة الاحتفاظ الخارجي حسب حاجة التشغيل، وتحقّق من نجاح مهمة النسخ عبر سجل الجدولة.

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 077
cd /srv/rawmat
compose=(docker compose --env-file deploy/.env -f deploy/compose.yml)
snapshot=$("${compose[@]}" exec -T app /nodejs/bin/node apps/server/dist/cli/database-backup.js create)
name=${snapshot##*/}
work=$(mktemp -d)
trap 'rm -rf -- "$work"' EXIT
"${compose[@]}" cp "app:$snapshot" "$work/$name"
age --encrypt --recipients-file /etc/rawmat/backup-recipients.txt \
  --output "$work/$name.age" "$work/$name"
rclone copyto "$work/$name.age" "backup-remote:rawmat/$name.age"
```

اعطِ السكربت إذن التنفيذ، وشغّله مرة بحساب الجدولة وتحقق من وصول ملف `.age` إلى الوجهة. أضف سطرًا مثل التالي إلى `crontab` لهذا الحساب، واستبدل المسار بمسار السكربت.

```cron
15 2 * * * /etc/rawmat/backup-nightly
```

## تجربة الاسترجاع محليًا

استخدم نسخة اختُبرت ملكيتها ومسارها، واحتفظ بالملف الأصلي. إذا أتيت بالنسخة من التخزين الخارجي، فكّ تشفيرها على الجهاز المخوّل داخل مجلد خاص بعد ضبط `umask 077`.

```sh
age --decrypt --identity /secure/rawmat-backup.key --output snapshot.sqlite snapshot.sqlite.age
```

من جذر المشروع، استخدم اسم مشروع جديدًا ومنفذًا محليًا شاغرًا. أنشئ صورة التطوير من المراجعة التي ستشغّلها، ثم استرجع النسخة قبل تشغيل الخادم حتى لا تنشأ قاعدة فارغة. ملف التطوير يستخدم التتبع اليدوي وتظل فيه تنبيهات n8n متوقفة.

```bash
export LOCAL_PORT=18081
recovery=(docker compose -p rawmat-restore -f deploy/compose.dev.yml)
"${recovery[@]}" build app
"${recovery[@]}" run --rm --no-deps -T --entrypoint /nodejs/bin/node app \
  apps/server/dist/cli/database-backup.js restore < snapshot.sqlite
"${recovery[@]}" up -d --wait
curl -fsS "http://127.0.0.1:$LOCAL_PORT/healthz"
```

يفحص أمر الاسترجاع سلامة القاعدة ثم يبطل الجلسات المحفوظة فيها. سجّل الدخول من جديد وراجع المواد والطلبات والشحنات، والحسابات وأدوارها وسجل التنبيهات. سجّل تاريخ الاختبار ومعرّف النسخة المختبرة ونتيجته، ونظّف الملفات المفكوكة ومشروع التجربة عند الانتهاء.

## استبدال وحدة بيانات التشغيل بعد التحقق

أوقف تطبيق الإنتاج خلال الاستبدال. احتفظ بوحدة البيانات القديمة للرجوع إليها، واستخدم وحدة البيانات الجديدة التي تأكدت من سلامتها. إذا أجريت التجربة على جهاز آخر، كرر أمر `restore` على الخادم في مشروع منفصل قبل الاستبدال. راجع تغييرات الحسابات منذ تاريخ النسخة، وأعد تطبيق تعطيل الحسابات وتغيير الأدوار وكلمات المرور قبل إتاحة الوصول العام. اجعل `TRACKING_PROVIDER=manual` وعطّل إعدادات n8n في ملفات بيئة الإنتاج، ثم راجع المستلمين وطابور الرسائل مع مسؤول التشغيل. قد تشمل النسخة تنبيهات قُبل إرسالها بعد أخذها.

لربط الوحدة الجديدة، أنشئ ملف Compose إضافيًا خارج المستودع. المثال يفترض استخدام مشروع التجربة `rawmat-restore` على الخادم نفسه. استخدم `stop` لإيقاف مشروع الاسترجاع قبل ربط وحدته بخدمة الإنتاج، واحتفظ بالوحدة بعد الربط.

```yaml
volumes:
  data:
    external: true
    name: rawmat-restore_data
```

مرّر هذا الملف بعد `deploy/compose.yml` في أوامر Compose اللاحقة، بما فيها النسخ الليلي. تحقق من الصحة وتسجيل الدخول عبر الوكيل قبل إعادة تفعيل التتبع والإرسال.
